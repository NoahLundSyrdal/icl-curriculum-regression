## What the new runs test

| Target | Strategy comparisons | Purpose |
| --- | --- | --- |
| 20 dimensions | Joint dimension/context curriculum, exact same batches shuffled, full difficulty | Independent replication at another dimension |
| 50 dimensions | Joint, dimension-only, context-only curricula, each with its own exact shuffled control, plus full difficulty | Distinguish the two curriculum components and replicate the original dimension |

Every strategy receives five learning rates and three fresh development seeds, trained for the full 125,000 updates. This extends the earlier learning-rate grid downward and replaces 50,000-update tuning with full-horizon tuning. It does not guarantee that the full-difficulty baseline will learn or that the grid contains an optimal configuration.

There are two distinct confirmation panels:

- **Ordering:** a shared learning rate chosen symmetrically from curriculum and shuffled development outcomes. Initialization, optimizer, realized batch multiset, shapes, loss masks, scaling and compute match; order changes.
- **Tuned strategies:** every strategy selects its own learning rate from the same candidate grid and development budget. This compares practical training strategies. A tuned curriculum/shuffled comparison does not isolate ordering if learning rates differ.

Each component selects its own shared setting. Its curriculum/shuffled contrast isolates ordering, but comparing effect sizes across components is not a single-optimizer factorial interaction test. Twenty fresh paired seeds enter confirmation. Identical configurations across panels reuse the same model and do not count as independent observations. The fixed arrays contain 150 development slots and 360 confirmation slots, of which 200..360 require training. Up to 15 GPUs run concurrently; success dependencies prevent development and confirmation overlapping.

## Frozen analysis

The primary endpoint is final clean late-context NMSE for joint curriculum versus matched shuffled at dimension 20. A support claim requires an exact two-sided paired sign-test p<0.05, geometric paired error ratio <=0.90 and curriculum arithmetic mean NMSE <=0.25. This endpoint was chosen prospectively using information from the previous study; it does not replace that study's original AUC analysis.

If the primary criteria pass, seven secondary clean comparisons use Holm correction. Otherwise they remain descriptive. All seeds, outliers, failed learning and boundary-selected learning rates are reported. Clean AUC, noise conditions SD1/SD2, peak ratios, bootstrap intervals and the independent final evaluation bank are descriptive. Raw noise levels are identical across dimensions, but relative noise-to-signal differs, so cross-dimensional noise differences do not isolate dimension.

## Exact implementation

The new adapter reuses byte-identical `run_experiment.py` and `robustness_experiment.py` from the verified original confirmation. The causal architecture, deterministic batch generation, training loss, AdamW loop, evaluation and RNG restoration remain unchanged. The adapter adds the new task settings and run identities and retains baseline, curriculum-boundary and final checkpoints plus a rolling restart checkpoint. Intermediate metric hashes remain available; intermediate weight binaries are not retained. No training noise is introduced in this study.

- [followup_plan.py](../experiments/followup_20261013/followup_plan.py): fixed task generation, equal development grid, symmetric shared-setting selection, independent tuning, exact alias resolution, source verification, sign tests and Holm.
- [followup_experiment.py](../experiments/followup_20261013/followup_experiment.py): task configuration, source/run identity, unchanged trainer adapter and independent final evaluation.
- [followup_checks.py](../experiments/followup_20261013/followup_checks.py) and [test_followup.py](../experiments/followup_20261013/test_followup.py): scientific preflight, pairing, target scale, leakage, restart and inference tests.
- [followup_analysis.py](../experiments/followup_20261013/followup_analysis.py): verifies every raw metric, retained checkpoint, schedule and initialization before selection/summary; writes all-seed results, baseline learning/failure groups and confirmatory/descriptive outcomes.
- [submit_followup.py](../experiments/followup_20261013/submit_followup.py): source freeze, saved Slurm receipts and success dependencies. Ambiguous or partial submissions are refused rather than repeated.
- [archive_followup.py](../experiments/followup_20261013/archive_followup.py): automatically archives raw text, code and provenance after successful summary; excludes weights and credentials.

## Reproduce or inspect

The study is staged separately from the archived experiment. To create a clean run from the repository root:

```bash
python3 tools/stage_followup.py --destination runs/followup-reproduction
cd runs/followup-reproduction
module purge
module load Python/3.12.3-GCCcore-13.3.0
python3 -m venv .venv
.venv/bin/python -m pip install -r ../../requirements-gpu.txt
.venv/bin/python submit_followup.py --preflight-only
# Only after the CPU preflight succeeds:
.venv/bin/python submit_followup.py
```

These commands submit substantial GPU work. The cluster requests use IDUN's existing share-ie-idi account, high QoS, GPUQ A100 80GB resources and CPUQ audit jobs. The original run is at `/cluster/work/noahls/icl-rerun-20261005/followup_20261013`, using the original recorded CUDA runtime. A fresh rerun with the same seeds is numerical reproduction, not another independent training cohort. The freshness audit intentionally rejects those seeds on a cluster that already contains this cohort; create a distinct prospective protocol for new statistical evidence.

The source freeze is verified on every production invocation. Confirmation cannot start without a complete, independently audited development cohort and locked selection. Interrupted infrastructure jobs can resume only the same task with `ICL_FOLLOWUP_RESUME=1`; completed poor-performing jobs cannot be replaced. Nonfinite training blocks downstream claims and is recorded as a failure.

Generated outputs:

- `submissions/freeze.json`, `pipeline.json`, `cpu-preflight.json`, `gpu-smoke.json`, `selection.json` and `resolved_tasks.json`: exact source, runtime, checks, jobs and configuration resolution.
- `results/development/` and `results/confirmation/`: every manifest, train log, primary/holdout evaluation, schedule and retained checkpoint.
- `results/summary.json` and `results/all_seed_results.csv`: results and all per-seed conditions/panels. Aliases include their canonical model ID.
- `results/followup_20261013.zip` and `results/archive_manifest.json`: complete raw text archive and checksum, generated automatically only after all confirmation jobs and audits succeed.

Model weights and binary schedules stay on IDUN. The final archive and summary can then be copied into this repo as a separately labeled result set. Do not pool this study's prospective tests with earlier exploratory cohorts.
